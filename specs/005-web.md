# 005 — Serviço web

Status: aprovada
Depende de: 001, 008, 009, 010, 011, 012, 014, 015

## Contexto
Atende as portas web capturadas. Detecta o protocolo pelos primeiros bytes (não pela porta), responde de forma
controlável pela URL, serve os arquivos estáticos e registra os bytes exatos recebidos e enviados.

## Requisitos
- RF-01: escuta TCP `FS_WEB_TCP_PORTS` (80, 443, 8080, 8443) e UDP `FS_WEB_UDP_PORTS` (443) nos IPs
  `FS_LISTEN_IPV4`/`FS_LISTEN_IPV6`.
- RF-02: detecção pelos primeiros bytes (`pkg/detect`): `0x16 0x03` → TLS; `PRI * HTTP/2.0` → h2c prior knowledge;
  método HTTP + espaço → HTTP/1.x; o resto → TCP cru (registrado como `raw/unknown`, modo sink). Vale para todas
  as portas: TLS na 80, HTTP em claro na 443.
- RF-03: depois do TLS, ALPN decide: `h2` → spec 010; `http/1.1` ou nenhum → spec 009.
- RF-04: UDP 443 → QUIC/HTTP/3 (spec 011). Enquanto o servidor h3 estiver ativo, respostas HTTP/1 e h2 em portas
  TLS anunciam `Alt-Svc: h3=":443"; ma=60` (desligável por `?alt_svc=0`). "Ativo" = `FS_WEB_UDP_PORTS` contém
  443 e o listener UDP 443 está de pé; sem ele, nada é anunciado e o heartbeat do web fica `degraded`
  (`h3_listener_down`). O campo entra em `response_sent` como qualquer outro, depois dos campos padrão e antes
  dos `h=`. Respostas de htdocs também anunciam (o navegador passa a h3 na mesma origem).
- RF-05: rotas:
  - `/p/<id>/` e `/p/<id>/r?...` → espelho controlado com probe;
  - `/r?...` → espelho controlado sem probe;
  - `/.well-known/acme-challenge/*` → ACME HTTP-01 (spec 015);
  - qualquer outro caminho → arquivo de `FS_HTDOCS` (spec 014) ou 404.
- RF-06: resposta padrão de `GET /p/<id>/`: 200 com corpo pequeno (texto) contendo `conn_id` e o índice da
  requisição na conexão. O `conn_id` vem do store por `fs.v1.store.conn_id`, pedido logo após o accept (ADR 0017);
  sem resposta em 250 ms, o corpo traz `conn_id: unknown`. `?inline=1` devolve no corpo o JSON da própria requisição (depuração por script; a página
  nunca usa).
- RF-07: controles de resposta (`/p/<id>/r?...`), registrados no evento como `controls` (com `clamped` quando um
  teto foi aplicado):

| Parâmetro | Efeito |
| --- | --- |
| `status=NNN` | código de status (inclusive 1xx; `103` Early Hints antes da final) |
| `ver=1.0\|1.1` | versão da linha de status |
| `size=N` | tamanho do corpo (máx `FS_SIZE_MAX`, 64 MiB) |
| `frame=cl\|chunked\|close` | Content-Length, chunked (`chunk=N`, `trailers=1`) ou até o fechamento |
| `conn=keep\|close\|none` | `Connection: keep-alive`, `close` ou nenhum |
| `ka=timeout,max` | `Keep-Alive: timeout=..., max=...` |
| `close=after\|before-body\|mid-body` | fecha após a resposta, antes do corpo ou no meio |
| `rst=1` | fecha com RST em vez de FIN |
| `delay_head=ms`, `delay_body=ms` | atrasos (máx `FS_DELAY_MAX`, 60 s) |
| `idle=s` | ociosidade mantida pelo servidor (padrão `FS_IDLE_DEFAULT` 120 s, máx `FS_IDLE_MAX` 600 s) |
| `h=Nome:Valor` (repetível) | campos extras na resposta, caixa e ordem exatas |
| `hsize=N` | cabeçalho de resposta grande (máx `FS_HSIZE_MAX`, 1 MiB) |
| `continue=send\|skip\|late` | tratamento de `Expect: 100-continue` |
| `upgrade=ws` | 101 e WebSocket em eco (spec 012) |
| `alt_svc=0` | não anunciar h3 |

- RF-08: o servidor **nunca fecha a conexão por conta própria antes de `idle`**, para que todo fechamento
  observado venha do cliente/proxy.
- RF-09: registra os bytes exatos enviados (`response_sent`) por requisição e o fluxo `out` completo, respeitando
  os tetos da ADR 0018 (inline até `FS_EVENT_INLINE_MAX`; fluxo até `FS_RAW_STREAM_MAX_BYTES` por sentido, com
  `in_offset`/`out_offset` por requisição).
- RF-10: publica eventos de aplicação (`fs.v1.web.*`) com a 5-tupla; buffer do produtor como na spec 003 RF-05.
- RF-11: dono do ACME (spec 015); certificados com recarga a quente.
- RNF-01: sustentar RNF-01 da spec 000.

## Comportamento
- Detecção: lê até 24 bytes ou 2 s; se não chegar nada (cliente espera o servidor), trata como TCP cru silencioso.
  Conexões tratadas como TCP cru (`raw/unknown`, modo sink) publicam `fs.v1.web.raw.session` no fim, com o schema
  do raw (spec 006), além do fluxo `in`.
- Valores inválidos em controles → 400 com explicação em texto, registrado.
- Erros de parse são registrados com os bytes crus e a conexão segue o que for possível (nunca pânico; fuzz).

  Ver [asyncapi.yaml](../eventbus/nats/asyncapi.yaml).

## Dados
Não persiste registros. Persiste certificados e conta ACME em `var/certs`, `var/acme`.

## Critérios de aceite
- [ ] TLS na porta 80 e HTTP em claro na 443 são detectados e respondidos.
- [ ] Cada controle de RF-07 tem teste de integração que confere os bytes enviados.
- [ ] Conexão ociosa com `idle=30` é fechada pelo servidor só após 30 s; sem `idle`, só após 120 s.
- [ ] `GET /index.html` serve o arquivo com `Content-Type: text/html; charset=utf-8`.

## Fora de escopo
- Reverse proxy; autenticação; compressão de resposta não pedida.
